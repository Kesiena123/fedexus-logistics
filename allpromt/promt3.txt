==================================================
LIVE FULL-WIDTH SHIPMENT TRACKING MAP
==================================================

Implement a professional live shipment tracking map on the public shipment tracking page.

The map must occupy the entire width of its parent tracking section.

Do not place the map inside a small narrow card or restricted column.

The map should be displayed as a full-width responsive section:

[================================================]
[                                                ]
[              LIVE TRACKING MAP                 ]
[                                                ]
[================================================]

The map must:

- Occupy 100% of the available section width.
- Be responsive on desktop, tablet, and mobile.
- Have a professional minimum height, such as 450px to 600px on desktop.
- Automatically adjust its height on smaller screens.
- Use the full available container width.
- Have rounded corners and a professional visual design where appropriate.
- Avoid unnecessary padding that makes the map appear narrow.

Use a real interactive map such as:

Leaflet.js + OpenStreetMap

The map must display real shipment data from the database for the exact tracking number.

Display:

- Origin marker
- Current shipment location marker
- Transit location markers
- Destination marker
- Route line/polyline
- Shipment movement direction where possible
- Location popup information
- Current shipment status
- Last updated time

==================================================
LIVE TRACKING BEHAVIOUR
==================================================

The map must be connected to the shipment's real tracking data.

When the Admin updates:

- Current shipment location
- Shipment status
- Tracking history
- Route points

the map must reflect the latest saved data.

Implement live or near-real-time updates using an appropriate method such as:

- WebSockets
- Laravel Broadcasting
- Server-Sent Events
- AJAX polling

Choose the most suitable implementation based on the existing project architecture and hosting environment.

If WebSockets are unavailable on the hosting environment, implement efficient AJAX polling as a fallback.

Do not reload the entire page unnecessarily.

The map should update only the relevant shipment tracking information.

The Guest must only receive live tracking information for the exact tracking number being viewed.

==================================================
MAP DATA FLOW
==================================================

Admin updates shipment location
        ↓
Location is validated
        ↓
Location is saved to the database
        ↓
Tracking event is created/updated
        ↓
Live tracking system broadcasts or retrieves the update
        ↓
Guest tracking page receives the latest data
        ↓
Map marker moves/updates
        ↓
Route updates if necessary
        ↓
Status and last-updated information refresh

==================================================
IMPORTANT MAP REQUIREMENTS
==================================================

The map must not use:

- Fake coordinates
- Random locations
- Hardcoded shipment data
- Static screenshots
- Placeholder markers

The map must use actual location data stored in the database.

If a shipment has no valid location data, display a professional message such as:

"Live location is currently unavailable. Tracking information will be updated when a new location is available."

Do not display a fake map location.

When the map loads, automatically fit the map view to display all available shipment locations and the route.

When the current shipment location changes, smoothly update the current marker and recenter the map where appropriate.

Do not unnecessarily recenter the map if the Guest is manually exploring the map unless appropriate.

The map must be fully functional and occupy the complete width of the tracking section.

==================================================
ADMIN PAYMENT REQUEST MANAGEMENT (FULL CONTROL)
==================================================

Upgrade the existing Payment Request system so that the Admin has complete ownership and control over every payment request.

The Guest must NEVER be able to create, edit, delete, cancel, modify, or approve any payment request.

Only the Admin can manage payment requests.

==================================================
ADMIN FEATURES
==================================================

Create a professional Admin → Payments → Payment Requests management module.

The Admin must be able to:

• Create unlimited payment requests
• Edit existing payment requests
• Delete payment requests
• Duplicate payment requests
• Enable or disable payment requests
• Activate or deactivate payment requests
• Cancel payment requests
• Expire payment requests
• Extend payment due dates
• Mark payment requests as completed (only after successful payment verification)
• Reopen payment requests when necessary
• Archive completed payment requests
• Restore archived payment requests

==================================================
PAYMENT REQUEST CREATION
==================================================

When creating a payment request, the Admin must be able to configure:

• Shipment
• Tracking Number
• Payment Title
• Payment Category
• Payment Reason
• Description
• Amount
• Currency
• Due Date
• Payment Priority
• Payment Instructions
• Internal Notes (Admin Only)

Select available payment methods:

☑ Flutterwave

☑ Stripe

☑ PayPal

☑ Cryptocurrency

☑ Manual Bank Transfer

The Admin decides which payment methods are available for each payment request.

==================================================
PAYMENT REQUEST STATUS
==================================================

The Admin has full control over the payment lifecycle.

Supported statuses include:

• Draft
• Payment Required
• Payment Initiated
• Processing
• Awaiting Verification
• Paid
• Failed
• Cancelled
• Expired
• Refunded
• Archived

Only authorized backend logic or the Admin may change these statuses.

Guests cannot change any status.

==================================================
MULTIPLE PAYMENT REQUESTS
==================================================

Support multiple payment requests for the same shipment.

Example:

Tracking Number:

GEL-2026-45891

Payment Requests:

Customs Clearance Fee

Storage Fee

Insurance Fee

Delivery Fee

Import Duty

Tax

Administrative Fee

Emergency Handling Fee

Each payment request must have:

• Unique Payment ID
• Unique Payment Reference
• Independent Status
• Independent History
• Independent Receipt

==================================================
ADMIN EDITING
==================================================

The Admin can edit a payment request before payment is completed.

Editable fields include:

• Title
• Reason
• Description
• Amount
• Currency
• Due Date
• Payment Methods
• Instructions
• Priority

All changes must immediately update the Guest Tracking Page.

==================================================
PAYMENT REQUEST HISTORY
==================================================

Every payment request must maintain a complete history.

Record:

• Created
• Updated
• Amount Changed
• Due Date Changed
• Payment Method Changed
• Activated
• Disabled
• Cancelled
• Paid
• Refunded
• Archived

Record:

• Date
• Time
• Admin User
• Previous Value
• New Value

==================================================
PAYMENT REQUEST VISIBILITY
==================================================

Guests can only view payment requests linked to the tracking number they searched.

Guests cannot:

• Browse payment requests
• Search other tracking numbers
• Access hidden payment requests
• View internal notes
• View Admin activity

==================================================
PAYMENT REQUEST SECURITY
==================================================

The Guest must NEVER be able to:

• Change the amount
• Change the currency
• Change the payment reason
• Change payment methods
• Modify due dates
• Cancel requests
• Approve payments
• Reject payments
• Mark payments as paid
• Create payment requests
• Delete payment requests

All payment values must always come from the Laravel backend.

Never trust data submitted from the browser.

==================================================
ADMIN DASHBOARD
==================================================

Create a professional Payment Request Dashboard showing:

• Total Payment Requests
• Active Payment Requests
• Outstanding Payments
• Paid Payments
• Failed Payments
• Awaiting Verification
• Expired Requests
• Total Revenue
• Revenue by Gateway

Provide filters for:

• Tracking Number
• Shipment
• Customer Name
• Payment Status
• Gateway
• Currency
• Date Range

==================================================
FINAL REQUIREMENT
==================================================

The Admin must have complete control over every payment request from creation to completion.

The Guest's role is limited to:

• Search shipment by tracking number
• View shipment details
• View active payment requests
• Select an enabled payment method
• Complete payment
• View payment history and receipt for that shipment only

The Guest must never have permission to create, edit, cancel, approve, reject, or manage payment requests.

Ensure all payment requests are integrated with the shipment system, tracking page, payment history, receipts, notifications, audit logs, and reporting. Test every workflow thoroughly before considering the implementation complete.
